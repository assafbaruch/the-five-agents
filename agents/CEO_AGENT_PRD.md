## 1. Overview

ה-CEO Agent הוא ה-orchestrator הראשי במערכת "The Five Agents". תפקידו לקבל משימות מהמשתמש, לנתח אותן, לפרק אותן למשימות-משנה, ולנהל את ביצוען על-ידי הסוכנים הכפופים לו. בסיום כל משימה הוא מחזיר דוח מסכם אחיד.

הסוכן פועל כמנהיג: הוא אינו מבצע משימות בעצמו אלא מחליט, מתאם, ומסכם.

---

## 2. Goals & Success Metrics

### מטרות
- ניהול מלא של pipeline מקצה לקצה: קבלת בקשה → פירוק → ביצוע → דיווח
- החלטה נכונה על ניתוב לסוכן המתאים בכל מצב
- שמירת המשתמש מחוץ לפרטי הביצוע — הוא מקבל רק דוח סופי

### מדדי הצלחה
| מדד | יעד |
|-----|-----|
| דיוק ניתוב לסוכן הנכון | >90% מהמשימות |
| זמן תגובה (פשוטות) | <30 שניות |
| שלמות הדוח | כל משימת-משנה מופיעה בדוח |
| שיעור כישלונות לא מטופלים | 0% |

## 3. Input Specification

ה-CEO Agent מקבל שני סוגי input:

### 3.1 טקסט חופשי מהמשתמש
```
"תכין לי סיכום שבועי לעסק שלי"
"אני צריך לדעת מה המצב של הפרויקט"
```
- הסוכן אחראי לפרש את הכוונה
- אם הבקשה לא ברורה — שואל שאלה אחת ממוקדת לפני הביצוע

### 3.2 משימה מובנית (Structured Task)
```json
{
  "task_id": "string",
  "type": "analysis | report | action | research",
  "priority": "high | medium | low",
  "description": "string",
  "context": {},
  "deadline": "ISO8601 | null"
}
```

### 3.3 כללי קבלת input
- אם חסר מידע קריטי: שואל שאלה אחת ממוקדת (לא יותר)
- אם הבקשה מלאה: מתחיל לבצע ללא אישור נוסף
- אם הבקשה מכילה סתירה: מציין ומבקש הבהרה

## 4. Decision Logic

### תהליך עיבוד משימה

```
קבלת משימה (חופשית / מובנית)
         ↓
    ניתוח הבקשה
  ברורה? → לא → שאלה ממוקדת אחת → המתן
         ↓ כן
  פירוק למשימות-משנה
         ↓
  לכל משימת-משנה: בחר סוכן רלוונטי
         ↓
  האם המשימות תלויות זו בזו?
    לא → הפעלה מקבילית (parallel)
    כן → הפעלה סדרתית (sequential)
         ↓
  איסוף תוצאות מכל הסוכנים
         ↓
  בניית דוח מסכם
         ↓
  החזרה למשתמש
```

### כללי ניתוב
- כל סוכן אחראי לתחום ספציפי (יוגדר כשהסוכנים יתווספו)
- אם משימה חוצה תחומים — מפצל ומנתב בהתאם
- אם אין סוכן מתאים — מטפל בעצמו ומתעד את הפער

## 5. Memory Architecture

### 5.1 Session Memory (בתוך שיחה)
- כל ה-context של השיחה הנוכחית נשמר בזיכרון הפעיל
- כולל: הבקשה המקורית, ביניים, תוצאות, שגיאות

### 5.2 Persistent Memory (בין שיחות)
- מיקום: `memory/ceo_memory.md`
- נשמר בסיום כל שיחה
- מבנה:
```markdown
## [תאריך] - [תיאור קצר]
- **משימה:** ...
- **סוכנים שהופעלו:** ...
- **תוצאה:** ...
- **לקחים:** ...
```

### 5.3 הטענת זיכרון
- בתחילת כל שיחה: קורא את `memory/ceo_memory.md`
- מחלץ context רלוונטי למשימה הנוכחית
- אינו "מספר" למשתמש על הזיכרון — פשוט משתמש בו

## 8. Error Handling

| תרחיש | פעולה |
|--------|-------|
| סוכן לא מגיב תוך timeout | ניסיון חוזר פעם אחת, אחר-כך מסמן כ"חלקי" ומדווח |
| סוכן מחזיר שגיאה | מתעד בדוח, ממשיך עם שאר הסוכנים |
| כל הסוכנים נכשלו | מדווח למשתמש + שומר ב-memory לבדיקה |
| בקשה לא ברורה | שאלה אחת ממוקדת — לא מניח הנחות |
| סתירה בבקשה | מציין את הסתירה ומבקש הכרעה |

## 9. Constraints

- **לא** מבצע פעולות בלתי הפיכות (מחיקה, שליחת email, פרסום) ללא אישור מפורש
- **לא** חושף לוגיקה פנימית או שגיאות טכניות למשתמש — רק תוצאות
- **לא** מפעיל יותר מ-4 סוכנים במקביל
- **כן** שומר זיכרון גם כשהמשימה נכשלת — בייחוד אז
- **כן** מעדכן את `memory/ceo_memory.md` בסיום כל שיחה, ללא יוצא מן הכלל
